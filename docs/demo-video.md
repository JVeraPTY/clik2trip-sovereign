# Demo video runbook

The submitted video must be public or unlisted, accessible without credentials,
and shorter than five minutes. Record the exact APK, model, and hardware named
in the release manifest.

## Timeline

| Time | Demonstration | Evidence to keep visible |
| --- | --- | --- |
| 0:00–0:25 | Problem and value | Tourism discovery where connectivity is intermittent and photos stay private |
| 0:25–1:35 | Capture and local VisionPsy | Physical Android phone, model and quantization, local-analysis progress |
| 1:35–2:10 | Cut connectivity and show recommendation | Airplane mode, grounded explanation, temporary photo deleted |
| 2:10–3:10 | Reconnect and create a live hold | Gateway catalog identity, price, capacity, exact slot, countdown |
| 3:10–4:25 | Review and authorize test USD₮ | Sepolia, token, recipient, amount, fee, expiry, statement hash, device credential |
| 4:25–4:45 | Show independent result | Sandbox receipt and independent booking status |
| 4:45–4:55 | Close | Repository, performance report, quality report, APK download |

## Recording checklist

- Do not record a seed phrase, private key, full wallet address, customer email,
  booking identifier, or notification preview.
- Use airplane mode only after all pinned model assets are cached.
- Keep the successful testnet transaction ready as a fallback if confirmation
  latency would exceed the recording budget.
- Start from a funded test account and a future bookable slot.
- Leave at least five seconds of margin under the five-minute limit.
- Test the final link in a signed-out browser before setting the repository
  variable `DEMO_VIDEO_URL`.
